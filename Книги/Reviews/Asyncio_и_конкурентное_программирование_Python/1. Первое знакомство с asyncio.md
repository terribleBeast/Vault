## 1.1. Что такое asyncio?

В синхронном приложении код исполняется последовательно.

==Конкурентность==. 
В Python 3.4 появилась библиотека `asyncio`, она включала декораторы и синтаксис генератора `yield from` для определения сопрограмм.
В Python 3.5 в самом языке была реализована полноценная поддержка сопрограмм и асинхронного программирования, для чего были добавлены ключевые слова async и await. Этот синтаксис, общий с другими языками программирования, например C и JavaScript, позволяет писать асинхронный код так, что он выглядит как синхронный. Такой асинхронный код проще читать и понимать, поскольку он похож на последовательный код, с которым большинство программистов хорошо знакомо. Библиотека `asyncio` исполняет сопрограммы асинхронно, пользуясь моделью конкурентности, получившей название *однопоточный цикл событий*.

С помощью библиотеки можно выполнять не только IO-bound операции, но и CPU-bound благодаря взаимодействию с механизмами многопроцессорности и многопоточности. 
## 1.2. Что такое ограниченность производительностью ввода-вывода и ограниченность быстродействием процессора.

Ограниченные операции - операции, для которых существует некоторое ограничение, устранив которое можно достичь большей производительности. 
Операции IO и CPU bound задачи обычно существуют бок о бок (пример с запросом на сайт, и обработкой полученных результатов).
## 1.3. Конкурентность, параллелизм и многозадачность 
### 1.3.1 Конкурентность

Конкурентное выполнение задач - одновременное (но не параллельное) выполнение задач.
Конкурентное поведение - переключение между задачами.

### 1.3.2 Параллелизм

Параллельное выполнение - выполнение параллельно (вместе).

![](разница_между_конк_и_паралл.png)
### 1.3.3. Различие между конкурентностью и параллелизмом

==Вытесняющая многозадачность==
Конкурентность возможна, когда несколько задач могут работать независимо друг от друга. Конкурентность реализуемо на машине с одним ядром, применив вытесняющую многозадачность.  Параллелизм возможен только на машине с двумя и более ядрами.


==Параллелизм подразумевает конкурентность, но обратное верно не всегда.== Многопоточное приложение, работающее на многоядерной машине, является и конкурентным, и параллельным. В этом случае имеется несколько задач, работающих одновременно, и два ядра, не зависимо исполняющих код этих задач. Но многозадачность допускает также наличие нескольких задач, работающих конкурентно, но так, что в каждый момент времени выполняется только одна.
### 1.3.4. Что такое многозадачность
Вытесняющая многозадачность - многозадачность, при которой операционная система сама решает как переключаться между выполняемыми задачами с помощью процедуры ==квантования времени==. Когда операционная система переключает задачи, мы говорим, что имеет место *вытеснение*.

Реализация зависит от ОС. Обычно используется несколько потоков, либо несколько процессов.

Кооперативная многозадачность - многозадачность, в которой переключение происходит явно в коде.

### 1.3.5 Преимущества кооперативной многозадачности
В asyncio использутся кооперативная многозадачность.

**Потребляет меньше ресурсов**

Во время переключения между потоками или процессами происходит *контекстное переключение*. ОС нужно сохранить всю информацию о работающем процессе или потоке, чтобы потом его возобновить. 

**Гранулярность**

ОС приостанавливает поток или процесс в соответствии со своим алгоритмом планирования, но выбранный для этого момент не всегда оптимален.


## 1.4. Процессы, потоки, многопоточность и многопроцессность 

### 1.4.1 Процесс

Процесс - это работающее приложение, которому выделена область памяти, недоступная другим приложениям.

Если машина с несколькими ядрами - процессы работают параллельно.
Если машина с одним ядром - процессы работают конкурентно, но с применением квантования времени. 

При использовании квантования ОС будет автоматически вытеснять работающий процесс по истечении некоторого промежутка времни и передавать процессор другому процессу.

### 1.4.2. Поток 

Поток можно представить себе, как облегченные процессоры. Это наименьшая единица выполнения, которая может управляться ОС. У потоков нет своей памяти, они пользуются памятью создавшего их процесса. Потоки ассоциированы с процессом, создавшим их. С каждый процессом всегда связан хотя бы один поток, называемый *главным*. Процесс может выделять дополнительные потоки, которые обычно называются *рабочими* или *фоновыми*. Это называется ==многопоточностью== Потоки могут работать параллельно на многоядерном процессоре, и ОС может переключаться между ними с помощью квантования времени. 


> [!NOTE] Title
> При многопоточности возможно ==состояние гонки==

Многопроцессорность.
Процесс может создавать дочерние процессы, которыми управляет, а затем распределяет между ними работу (модуль `multiprocessing)`.


> [!NOTE] Title
> Многопоточность предпочтительна, когда имеется счетная задача.

Многопоточность и многопроцессность могут показаться волшебной палочкой, обеспечивающей конкурентность в Python. Однако развернуться во всю мощь этим моделям мешает одна деталь реализации Python – глобальная блокировка интерпретатора.

## 1.5. Глобальная блокировка интерпретатора 

GIL - мьютекс, который запрещает Python-процессу исполнять более одной команды байт-кода в каждый момент времени.


> [!NOTE] Для чего нужен GIL?
> В CPython использует механизм управления памятью, называемый подсчетом ссылок. Несколько потоков могут использовать взаимодействовать с одной областью памяти. Поэтому может возникать конфликт потоков из-за того, что интерпретатор CPython не является потокобезопасным. Это называется состояние гонки.   

![](race_condition.png)
``` python
import time
import threading

def print_fib(number: int) -> None:

    def fib(n: int) -> int:

        if n == 1:
            return 0
        elif n == 2:
            return 1
        else:

            return fib(n - 1) + fib(n - 2)
            
    print(f"fib({number}) equivalent {fib(number)}")

def fibs_no_thread():

    thread_40 = threading.Thread(target=print_fib, args=(40,))
    thread_41 = threading.Thread(target=print_fib, args=(41,))

    thread_40.start()
    thread_41.start()

    thread_40.join()
    thread_41.join()

start = time.time()

fibs_no_thread()

end = time.time()

print(f"{end - start:4f}")
```


#### Почему GIL освобождается при I/O bound задачах?
Так как ввод/вывод использует низкоуровневые системные вызовы за пределами Python, поэтому ОС не взаимодействует с Python объектами напрямую. GIL начинает работу снова, когда данные переносятся в объект Python. Значит, на уровне ОС операции ввода/вывода выполняются конкурентно. Это модель обеспечивает конкурентность, но не параллелизм. В других языках, например, C++ и Java GIL нет, поэтому в них на многоядерных машинах можно реализовать истинные параллелизм. Но в Python лучшее на что можно рассчитывать, - конкурентность операция ввода вывода, поскольку в любой момент времени может выполняться лишь одна байт-инструкция Python.

### 1.5.2 Asyncio и GIL

В asyncio используется тот факт, что I/O bound операции освобождают GIL, что позволяет реализовать конкурентность даже в одном потоке. При работе с asyncio мы создаем объекты сопрограмм. Сопрограмму можно представлять себе как облегченный поток. Точно так же, как может быть несколько потоков, работающих одновременно и исполняющие операции ввода-вывода, так может существовать много сопрограмм, работающих бок о бок. Ожидая завершения сопрограмм, занимающихся вводом-выводом, мы можем выполнять другой Python-код, получая таким образом конкурентность. Важно отметить, что asyncio не обходить GIL, мы по-прежнем ограничены им. Если имеется счетная задача, то для её  конкурентного выполнения все равно нужно заводить отдельный процесс (и в `asyncio` есть для этого средства), иначе производительность снизится.
